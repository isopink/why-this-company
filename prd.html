지원 산업 경험이 거의 없는 학사 신입 취준생을 위한 — 공시(DART) 기반 회사별 지원동기 초안 도구
skill-to-service · 단계 B · PRD (에이전트가 읽고 그대로 만들 설계도)
1

한 줄 정의

지원 산업 경험이 거의 없는 학사 신입 취준생이, 특정 회사·직무를 고르면 공시(DART)에서 찾은 회사 고유 숫자와 회사가 직접 쓴 위험요소로 지원동기 초안을 회사별로 쓰게 해주는 서비스. 문장을 대신 쓰지 않고, 근거 붙은 질문을 하나씩 던져 사용자가 직접 답을 적게 한다.

2

타깃 사용자

누구

지원 산업 경험이 거의 없어 "왜 이 회사인가"의 근거를 못 찾는 학사 신입 취준생.

구체: 산업공학 4학년, 하반기 공채에서 3개 산업 × 3개사 지원 예정.

지금 어떻게 쓰는지

  • 홈페이지·뉴스를 보고 쓴다
  • 회사명만 바꾸면 다른 회사에도 통하는 문장이 나온다
  • 회사별 근거가 약하다
3

문제

  1. 회사별로 쓸 근거가 약해서 지원동기 초안이 일반론으로 흐른다.
  2. AI·자소서 도구가 써준 문장은 근거가 없어 면접에서 "왜 그렇게 보셨어요"에 막힌다.
  3. 공시 읽기 자체에 2~3시간이 들어 시즌 중 반복(9개 회사)이 부담이다.
4

트리거 — 언제 스스로 오는가, 언제 불러 쓰는가

세 시점:

1 공고 확인 직후 →
2 지원동기 작성 중 →
3 면접 준비
  • 공고 확인 직후 — 무엇을 조사할지 모를 때, 볼 곳을 한 번에 좁혀줌
  • 지원동기 작성 중 — 초안이 일반론으로 흐를 때, 회사 고유 숫자·방향성 후보를 질문으로 줌
  • 면접 준비 — 서류에 쓴 숫자의 출처와 받을 질문을 준비
집중 시점
9~10월 하반기 서류 시즌 — 반도체·바이오·디스플레이, 방산·조선·기계·건설 대기업 정기 채용.

#기능설명우선순위
1 직무 선택 6계열 원형 UI에서 하나 선택 — 공정·생산 / R&D / 기획·전략 / 개발(SW·데이터) / 영업·마케팅 / 재무·구매(SCM). 자유 입력 없음, 분류 오류 방지. P0
2 회사 선택 ① 그래프: 고른 직무 계열을 뽑는 주요 기업이 연결선으로 표시, 원 크기 = 해당 회사가 열어둔 직무 계열 수. ② 없으면 같은 화면 검색 — DART 고유번호 부분 일치, 상장사 우선, 종목코드 표시. 후보 밖 자유 텍스트 제출 불가. P0
3 공시 기반 질문 흐름 질문 하나 = 화면 하나. 구성: 어느 주목할 사항에서 나온 질문인지 / 질문 한 문장 / 근거(수치, 판정 기준, 원문 위치 + DART 링크, 매핑 테이블 좌표) / 답 입력칸 / 이어질 꼬리질문(접어두고 펼침).
순서: 공시 질문 3개 → 회사가 직접 밝힌 위험요소(원문 그대로, 판정 안 함. "회사가 이렇게 썼는데 어떻게 답하겠는가") → 공통 질문 2개 → 답변 모아보기		 P0
4 답변 모아보기 + txt 다운로드 + 결과 주소 질문 + 내 답이 한 장씩 정리, txt 내려받기, 결과 주소(URL)로 이어서 쓰기. localStorage에 내가 쓴 답·본 리포트 목록 저장(서버 저장 없음). P0

입력 · 출력

입력 (순서 고정, 뒤로 못 돌아감)

단계내용
① 직무 6계열 원형 UI에서 하나 선택 — 공정·생산 / R&D / 기획·전략 / 개발(SW·데이터) / 영업·마케팅 / 재무·구매(SCM). 자유 입력 없음.
② 회사 ① 그래프 선택: 고른 직무 계열을 뽑는 주요 기업이 연결선으로 표시, 원 크기 = 해당 회사가 열어둔 직무 계열 수.
② 검색(그래프에 없으면): 같은 화면 DART 고유번호 부분 일치 검색, 상장사 우선, 종목코드 표시. 후보 밖 자유 텍스트 제출 불가.
③ 자료 (선택) 파일 업로드 칸 하나 + 종류 선택 (지속가능경영보고서 / CES·IR 발표자료). 없어도 진행. 세션 안에만 쓰고 저장 안 함. 공시 수치와 섞지 않고 리포트에 수치로 넣지 않음.

학점·경력·연락처 같은 개인정보는 받지 않는다.

1 자료 업로드 (선택)
→

각 화면 구성:

  • 어느 주목할 사항에서 나온 질문인지
  • 질문 한 문장
  • 근거 — 수치, 판정 기준, 원문 위치와 DART 링크, 매핑 테이블 좌표
  • 답 입력칸
  • 이어질 질문(꼬리질문) — 접어두고 펼쳐 봄

마지막 화면:

  • 질문 + 내 답이 한 장씩 정리
  • txt로 내려받기
  • 결과 주소(URL) 보여줌 — 저장해 두면 쓰던 답을 이어서 쓸 수 있음

표현 규칙:

  • "문제" 대신 "주목할 사항"
  • 금액은 조와 억을 함께 쓰고 반올림 금지
  • 연결/별도 기준 항상 표기
  • 판정 불가·파싱 같은 내부 용어는 화면에 쓰지 않음
  • 방향성 명사구를 나열하지 않음 — 문장을 반쯤 완성해주면 그대로 복사하게 되고, 면접에서 왜 그렇게 썼는지 설명하지 못하기 때문. 대신 질문으로 답을 받는다.

필요 설정

8-1. 배포 연결 (값 취급 없음)

  • 배포 방식: Vercel 함수 단위 서버리스가 아닌 상시 실행 호스팅. 규정 제8조 6항은 배포 플랫폼을 제한하지 않으며, Vercel은 가이드 기준일 뿐입니다. 예선 스크립트(judge·render·verify)를 서버에서 그대로 실행 — 파이썬 서브프로세스 실행, 작업 폴더 쓰기, 60초 이상 실행이 필요하기 때문입니다.
  • 프론트는 같은 도메인 /api만 fetch. /api는 PRD 6번에 적힌 공개 데이터 출처(OpenDART, 선택 KIPRIS)만 호출.
  • 클라이언트(index.html)에는 키·프록시 주소 0개.

8-2. 서비스 키 — Vercel 환경변수 (이름·용도·발급처만, 값 금지. 사용자가 직접 넣음)

8-3. 사용자 프로필 — 웹 화면 입력 → localStorage 저장 (재방문 시 묻지 않음, 초기화 버튼 제공. 서버 저장 없음)

  • 리포트 본문은 저장 안 함 (공시 과거 데이터, 같은 입력이면 같은 결과, 서버 캐시 3초).
  • 삭제 가능: 항목별 삭제 + 전체 초기화 (공용 컴퓨터 전제).
  • 저장값이 없는 첫 방문: "이어서 쓰던 것" 없이 바로 직무 선택 (빈 화면 금지). 시크릿 창 테스트 기준과 맞물림.
9

데이터 규칙

  • 출처·기준 시각 표기: 모든 수치는 출처(사업보고서 연결 기준, rcpNo 링크) 표기. KIPRIS 표기 시 "분석 판단 미사용" 명시.
  • 없는 값은 '확인 불가'로 표기. 추정 금지.
  • 키·프록시 주소는 서버(/api)에만. 클라이언트 소스·응답 JSON에 0개.
  • 최소 권한: /api는 PRD 6번 공개 데이터 출처만 호출, 그 외 외부 주소로는 요청하지 않음. 예선 스킬의 스크립트를 호출해 서비스의 판정·렌더·검증 엔진으로 쓰고, 매핑 테이블과 판정 기준을 유일한 지식 원천으로 한다.
  • 업로드 자료에서 나온 내용은 공시 수치와 섞지 않고, 리포트에 수치로 넣지 않음 (텍스트만).
  • 수치는 조+억 함께, 반올림 금지, 연결/별도 기준 항상 표기. 내부 용어(판정 불가·파싱·룰 등) 화면에 금지.
  • 판정 결과를 부르는 말은 "주목할 사항". 번호는 "주목 N.".
10

성공 기준 — 데모 시나리오로 검증 가능한 조건

반드시 시크릿 창 테스트 포함 — 계정·저장값 없는 브라우저로 첫 방문했을 때 안내가 스스로 나오고 최소 기능이 도는가.

#조건우선순위
1 시크릿 창 테스트 — 시크릿 창의 첫 방문에서 안내가 스스로 나오고, 최소 기능(직무 선택 → 회사 선택 → 질문 하나 받기)까지 동작한다. P0
2 직무 선택 — 6계열 원형 UI에서 하나를 고르면 다음으로 진행된다. P0
3 회사 선택 — 그래프 또는 검색으로 회사를 고르면 분석이 시작된다. 후보 밖 자유 텍스트는 제출되지 않는다. P0
4 질문 흐름 — 질문 하나(화면 하나)가 열리고, 근거(수치·판정기준·원문 위치+DART 링크·매핑 테이블 좌표)가 보이고, 답 입력칸이 있다. P0
5 답변 저장·이어가기 — 답을 입력하면 localStorage에 저장되고, 결과 주소로 돌아왔을 때 이어서 쓸 수 있다. P0
6 다운로드 — 답변 모아보기에서 txt 다운로드가 된다. P0
7 키 비노출 — 클라이언트 소스(index.html)와 /api 응답 JSON에 키·프록시 주소가 0개다. P0
8 /api 외부 주소 일치 — /api가 호출하는 외부 주소 목록이 PRD 6번과 일치한다 (그 외 요청 없음). P0
11

제외 범위

  • 자소서 문장 대신 작성 (방향성까지만, 문장화 금지)
  • 최신 뉴스·CES·IR 동향 등 공시 밖 정보를 판정에 사용 (v2로 분리됨 — 현재는 v1 범위)
  • 워크넷 채용공고 자격요건 자동 반영, 수시공시 기반 "최근 동향" 섹션, web-research로 최근 12개월 1차 출처 확인 (v2 — 본선 스킬 문서 명시, 현재는 제외)
  • 비상장사·DART 미등록 기업의 공시 기반 방향성 (공시 없음 → 정직 종료)
  • 업로드 자료에서 수치 추출·verify 대조 (홍보 자료라 기준 달라 불가능. 텍스트만 사용)
  • 서버 사용자 데이터 저장 (localStorage만, 서버는 작업 ID + 캐시만)
  • 다른 예선 스킬 호출 — seoul-parking-info 등은 접점 없어 호출하지 않음. 결선 서비스는 why-this-company 하나만 사용
