# scripts/ 명세 (실행 코드)

이 폴더는 스킬이 실행하는 코드가 들어가는 곳이다.  
이번 턴에는 실행 코드 없이 **명세 확정**까지만 진행한다.  
실제 코드는 다음 턴에 `dart_client.py`부터 작성한다.

## 방향

- OpenDART API 직접 호출 방식으로 간다.
- API 인증키는 스크립트에 하드코딩하지 않는다. 환경변수나 별도 설정으로 분리한다.
- 키는 스크립트에 절대 들어가지 않는다. 스크립트에서는 `os.environ` / `os.getenv`로 읽는다.
- 이 환경에서 키 지속(다음 턴 이후도 같은 키를 다시 치지 않는 방식) 가능 여부는 확인 후 반영한다. 확인이 불명확하면 이번 실행분만 환경변수로 주입하고, 지속 방법은 명세로 남긴다.

## 스크립트 3분할

### ① dart_client

**입력**
- 기업명
- (선택) 직무, 산업 맥락

**출력 (구조화된 데이터)**
- 기업 고유번호 / 기업명
- 최근 2개 정기보고서 목록 (rcpNo, 제목, 날짜 포함)
- 매출 구성: 지역 / 제품 / 고객별, 3개년
- 원재료 매입처
- R&D 실적
- 위험요소 서술
- 지속가능보고서: 있음/없음 여부와 원문 링크 + 읽을 관점 (본문 파싱 시도하지 않음)

**예외 처리 (반환값에 포함)**
- 기업명 미매칭/오타 → 유사 후보 목록 반환
- 비상장/공시 없음 → 해당 상태 코드 반환
- 표 파싱 실패 → 실패 항목 명시 + 원문 rcpNo 링크 반환 (숨기지 않음)
- API 무응답 → 재시도 1회 후 실패 보고

### ② judge

**입력**
- ① dart_client의 구조화된 데이터

**출력**
- 문제 판정 목록:
  - 편중: 상위 1-2개 항목 비중 합 ≥ 70%
  - 급변(확대): 전년 대비 비중 +10%p 이상
  - 급변(축소): 전년 대비 비중 -10%p 이상
  - 의존: 매입처·고객이 소수 지정으로 명시
  - 정체/역성장: 특정 부문 매출 2년 연속 감소
  - 투자 확대: R&D 비중 상승 또는 신규 시설투자 공시
- 각 판정에 **판정 근거 문자열**을 태깅해서 반환
  - 예: "의존 판정 — K-IFRS 주요고객 공시 기준(10%) 초과"

**판정 방식은 룰 기반**. LLM은 관여하지 않는다.

### ③ verify

**실행 시점**
- 최종 응답 직전

**작업**
- 응답에 등장하는 모든 수치를 ①의 원본 데이터와 재대조
- 불일치 → 원본 값으로 교체
- 원본에 없는 수치 → 해당 문장 삭제

**목적**
- 이 스킬의 최대 실패 모드(숫자 오류)를 구조로 방지한다.

## 스크립트가 하지 않는 것

- 문제 → 지원동기 방향성 연결은 하지 않는다.
- 방향성 선택과 문장화는 하지 않는다.
- 이 영역은 스킬(에이전트)이 `references/`의 매핑 테이블을 참조해 수행한다.
- 스크립트는 **사실 수집과 판정, 검증까지만** 책임진다.

## 예외 처리 요약 (반환값 기준)

| 상황 | 응답 |
| --- | --- |
| 기업명 미매칭/오타 | 유사 후보 목록 반환 후 재입력 요청 |
| 비상장/공시 없음 | 해당 상태 코드 반환, 대체 경로 안내 |
| 표 파싱 실패 | 실패 항목 명시 + 원문 rcpNo 링크 반환 |
| API 무응답 | 재시도 1회 후 실패 보고 |

## 구현 상태 (완료)

- `scripts/dart_client.py` — corpCode·document ZIP 로컬 캐시, 실패 시 5초 후
  1회 재시도, 재무는 fs_div == "CFS"(연결)만 사용(없으면 OFS 폴백 + 기준 명시),
  사업의 내용 4개 섹션 추출, 파싱 실패는 parse_ok=False 로 정직하게 보고
  - 섹션 위치는 표 신호 점수(셀 구분자·콤마 숫자·%)로 고르고, 점수가 최소치
    미만이면 본문이 아니라 목차·단순 언급으로 보고 미발견 처리한다
  - 사업부문명은 코드에 적어두지 않는다. 셀 흐름에서 "숫자 셀 2개 이상 앞의 가장 왼쪽 라벨"을
    항목명으로 자동 추출한다. DART 원문은 셀마다 줄바꿈이 들어와 행 단위 파싱이 모든
    실기업에서 실패했다(아모레·삼성전자·농심 실측) — 셀 기반으로 바꾼 뒤 아모레퍼시픽
    실데이터에서 화장품 89.2% / 헤어앤뷰티 10.8% 도출 확인
  - 가로형 비중 표(라벨 행 + "비중 | 44% | 9% | 47%")는 _parse_horizontal_pct 가 처리한다
  - 매입처는 표 머리글에서 '매입처' 열의 위치를 찾아 그 열만 읽는다
    (열을 특정하지 않으면 첫 열의 원재료명이 매입처로 잡힌다)
  - R&D 비중은 연구개발 관련 앵커 주변 구간에서만 수집하고 정수 퍼센트도 인식한다
  - 각 섹션 노드에 raw_head(공백을 접은 머리글 최대 1,500자)를 넣는다 — 파싱 실패 시
    표 구조를 눈으로 확인하기 위한 진단용. 500자일 때는 "다수의 제분사" 문장이
    잘려 의존 오판이 났다
  - period_no: 문서 앞부분 "제N기"에서 기수 추출. 없으면 null (리포트는 그때 기수를 쓰지 않는다)
  - 매입처 폴백에서 단위어(Ton·kg 등)와 4글자 미만 토큰을 제외한다
  - 매입처 열은 "뒤에서 몇 번째"로 잡는다 — 부문 셀이 rowspan 으로 병합된 행은 앞 셀이
    빠져 열 번호가 밀린다(삼성전자: DX 부문·품목명이 매입처로 잡힌 사고). 한 셀의
    "Qualcomm, MediaTek 등"은 사명별로 쪼갠다
- `scripts/judge.py` — 룰 6종 판정 + 근거 태깅. 미판정/판정 불가 구분,
  항목 2개 이하면 상위 1개만 편중 판정(2부문 회사 오판 방지)
- `scripts/render.py` — 리포트 전문 생성. 1단계(잘하는 것·문제·특이사항 없음·읽지 못한 항목),
  [출처]·[판정 기준]·[특허 동향]·[더 볼 것]·[저장]을 JSON 에서 기계적으로 만들고, Solar 가
  쓴 work/angles.txt(2·3단계)만 끼워 넣는다. 58자 줄바꿈, 절 순서 고정, 내부 용어 치환,
  0건이면 "방향성 미제시"로 고정. 사고 이력: 판정 0건 때 Solar 가 템플릿을 버리고
  판정 불가 항목을 문제로 포장·판정 안 된 매핑 칸을 사용 → 뼈대를 코드로 옮김
- `scripts/verify.py` — 리포트의 모든 수치를 원본과 재대조. 파생 %는
  분모를 매출 3개년으로 한정해 ±0.5%p 재현 검증(우연 일치 오탐 통과 차단).
  SKIP_BLOCKS에 [최신동향]이 등록돼 있으나 v1에서는 이 절을 출력하지 않는다
  (v2 web-research 연동 대비용, 현재 동작에 영향 없음)
- `scripts/kipris_client.py` — 출원인명 검색으로 최근 3년 출원 건수·기술
  키워드 추출(기업당 1회, 월 1,000건 한도 보호). 키 없음·0건·파싱 실패 시
  ok:false 반환으로 본편에 영향 없음. 판정 미사용(판정은 DART, 살은 KIPRIS)
- 키는 타임리 환경변수 OPEN_DART_API_KEY, KIPRIS_API_KEY 에서 읽는다. 하드코딩·.env 미사용
